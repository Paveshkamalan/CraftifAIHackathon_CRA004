## 1. What Actionable Output Means in AdaPipe

In production edge-AI deployments, an automated vision pipeline is only as valuable as its downstream utility. A pipeline that performs inference but merely renders visual boxes onto an on-screen display (OSD) cannot trigger real-world actions.

**Actionable Output** in AdaPipe refers to the systematic transformation of raw per-frame tensor inferences into **structured, strongly typed, and deduplicated event records** that external systems (building management controllers, access gates, occupancy analytics databases, and MQTT message brokers) can ingest programmatically.

Instead of requiring external applications to parse raw video streams or infer object lifetimes, AdaPipe provides:
1. **Per-Detection Events (JSONL Stream):** Real-time, line-delimited records emitted per frame for low-latency streaming ingestion.
2. **Aggregated Entity Manifest (JSON Summary):** A consolidated summary detailing unique individuals observed, tracking lifetimes, mean confidence scores, and spatial dwell zones.
3. **Identity Deduplication:** Spatial track association ensuring that the same person observed across consecutive frames is **not** incorrectly counted as multiple visitors.
4. **Optional MQTT Live Dispatch:** Low-overhead publish-subscribe telemetry forwarding events to enterprise IoT brokers without blocking the core video loop.

## 2. How PipeGen Generates Detection Metadata

The vision pipeline generated by **PipeGen** under `pipegen_output/generated_pipeline/` outputs structured tensor arrays from each video frame:

### 2.1 Inference Execution
In `pipegen_output/generated_pipeline/pipeline.py`, the input video frame is preprocessed into a normalized tensor:
- Shape: `[1, 3, 640, 640]`, Float32, RGB channel order, normalized to $[0.0, 1.0]$.
- Executed via `session.run(...)` on DeepStream / ONNX Runtime.

### 2.2 Output Tensors
The model produces three synchronized output tensors:
1. **`boxes` (`[1, 10, 4]`):** Normalized bounding-box coordinates $[y_{\min}, x_{\min}, y_{\max}, x_{\max}]$.
2. **`scores` (`[1, 10]`):** Confidence scores ranging from $0.52$ to $0.88$.
3. **`classes` (`[1, 10]`):** Integer class labels (`0 = person`).

### 2.3 Confidence Masking
PipeGen filters raw model proposals against the configured confidence threshold (`confidence_threshold: 0.40` in `config.yaml`):
```python
valid_mask = scores >= conf_thresh
valid_scores = scores[valid_mask]
valid_boxes = boxes[valid_mask]
```
All valid bounding boxes and confidence scores are packaged directly into the per-frame execution metrics dictionary and dispatched to the actionable event pipeline.

## 3. How Metadata is Converted into Structured Events

Raw bounding boxes from individual frames cannot directly answer business questions like *"How many unique individuals passed through the doorway?"* because a single person walking through the scene appears in 30 to 150 consecutive frames.

AdaPipe solves this through three conversion stages in `adapipe/actionable_output.py`:

### Stage 1: Spatial Track Association
The `SpatialTracker` maintains active object tracks across consecutive frames using Intersection over Union (IoU) and normalized Euclidean centroid distance:
$$\text{IoU}(A, B) = \frac{\text{Area}(A \cap B)}{\text{Area}(A \cup B)}$$
- If $\text{IoU} \geq 0.25$ between a new detection and an active track, the detection is associated with the existing `tracking_id`.
- The track updates its lifetime counter (`total_hits`), last observed box, and running confidence list.
- If no active track matches, a new `tracking_id` is allocated, and the event is tagged with `is_new_entity: true`.

### Stage 2: Deduplication Discipline
- **Conscious Distinction:** Each frame detection emits a frame-level event (recording exact instantaneous position and confidence), but the `is_new_entity` flag is only `true` on the initial observation frame.
- **Directional Tracking Rule (Prompt Compliance):** As required by Track A hackathon guidelines, because physical line-crossing tripwires and calibrated directional homography are not present in the baseline single-camera model, AdaPipe **does not fabricate entry and exit counts**. Instead, it reports genuine `person_detected` events with verifiable spatial zone localization.

### Stage 3: Spatial Zone Mapping
Each bounding box's normalized centroid $(c_x, c_y)$ is mapped to entrance zones:
- $c_y \geq 0.70 \rightarrow$ `"door_threshold"`
- $c_x < 0.35 \rightarrow$ `"entryway_left"`
- $0.35 \le c_x \le 0.65 \rightarrow$ `"entryway_center"`
- $c_x > 0.65 \rightarrow$ `"entryway_right"`

## 5. How Another Application Can Consume the Output

### Pattern A: Consuming the Streaming JSONL File (Python)
Ideal for batch analytics, data lakes, or background audit workers:

```python
import json

def process_stream(jsonl_path: str = "results/actionable_events.jsonl"):
    unique_visitors = set()
    with open(jsonl_path, "r", encoding="utf-8") as f:
        for line in f:
            if not line.strip():
                continue
            event = json.loads(line)
            # Count only new entity appearances to avoid duplicate counting
            if event.get("is_new_entity"):
                unique_visitors.add(event["tracking_id"])
                print(f"[NEW PERSON] ID {event['tracking_id']} entered {event['spatial_zone']} at {event['timestamp']}")
    print(f"Total Unique People Detected: {len(unique_visitors)}")

if __name__ == "__main__":
    process_stream()
```

### Pattern B: Consuming via MQTT (Node.js / Python Subscriber)
Ideal for building automation, security consoles, and smart door controllers:

```python
import json
import paho.mqtt.client as mqtt

def on_message(client, userdata, msg):
    payload = json.loads(msg.payload.decode("utf-8"))
    print(f"[ALERT] {payload['event_type']}: Track {payload['tracking_id']} in {payload['spatial_zone']} (conf: {payload['confidence']})")

client = mqtt.Client()
client.on_message = on_message
client.connect("localhost", 1883, 60)
client.subscribe("adapipe/events/person_detection")
client.loop_forever()
```
